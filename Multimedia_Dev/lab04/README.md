# Лабораторна робота №4 — Предиктори PNG

**Спеціальність:** 122 Комп'ютерні науки  
**Група:** КН-3/1  
**Дисципліна:** Розробка мультимедійних застосунків  

## Опис роботи
У ході лабораторної роботи реалізовано низькорівневі фільтри PNG (**None**, **Sub**, **Up**), а також алгоритм адаптивного вибору оптимального фільтра для кожного рядка на основі мінімізації суми абсолютних різниць (`sum_abs`). Досліджено вплив фільтрації на ентропію за Шенноном для 4 типів зображень.

---

## Завдання 2 & 5. Підсумкова таблиця ентропій та виграшу

| Тип зображення | Ентропія До | None | Sub | Up | Адаптивний | Оптимальний фільтр | Виграш, % |
|---|---|---|---|---|---|---|---|
| **Градієнт** | 8.00 | 8.00 | 1.00 | 0.05 | 0.01 | Up | **99.9%** |
| **Білий шум** | 8.00 | 8.00 | 8.00 | 8.00 | 8.00 | None / Хаотично | **0.0%** |
| **Скріншот** | 2.40 | 2.40 | 0.10 | 0.46 | 0.08 | Up / Sub | **96.7%** |
| **Фотографія** | 7.20 | 7.20 | 5.60 | 5.60 | 5.48 | Sub / Up | **23.9%** |

---

## Висновок
1. **Чому для градієнта виграш майже 100%:** Рядки горизонтального або вертикального градієнта повторюють один одного або мають постійний крок. Фільтр `Up` віднімає верхній однаковий рядок, перетворюючи майже всі значення на нулі, через що ентропія падає від 8.00 майже до 0.
2. **Чому для білого шуму виграш 0%:** У випадковому білому шумі пікселі не мають кореляції із сусідніми. Віднімання сусідніх значень дає такий самий випадковий шум, тому ентропія залишається рівною 8.00 біт/піксель.
3. **Чому фотографія має проміжний результат (~24%):** Реальні фотографії містять плавні переходи й текстури, тому сусідні пікселі близькі за значенням, але мають природний шум. Фільтрація зменшує амплітуду значень, але не може обнулити її повністю.

## Відповіді на контрольні запитання
1. **Де береться лівий сусід:** Формується як `cur[:-1]` зі зсувом на 1 елемент праворуч (`np.concatenate(([0], cur[:-1]))`). Для найпершого пікселя лівий сусід вважається рівним `0`.
2. **Чому для градієнта Up дає ~0, а Sub дає ~1:** Оскільки вертикально сусідні рядки градієнта однакові, їхня різниця дає суцільні нулі (фільтр `Up`). Горизонтально ж пікселі зростають на сталий крок, тому різниця дає постійне число (фільтр `Sub`), що відповідає 1 біту ентропії.
3. **Чому фільтрація без втрат:** Віднімання та додавання по колу (`% 256`) є взаємно зворотними арифметичними операціями в кільці $\mathbb{Z}_{256}$.
4. **Переведення > 127 у від'ємні при `sum_abs`:** Значення 250 в арифметиці `% 256` насправді відповідає відхиленню на $-6$. Без переведення алгоритм помилково вважав би це великим відхиленням.
5. **Чому фільтри не допомагають шуму:** Оскільки випадкові величини незалежні, віднімання двох незалежних рівномірних розподілів не зменшує їхню сукупну ентропію.
6. **Чому кожен рядок може мати свій фільтр:** Рядки реального зображення можуть містити різні графічні елементи (наприклад, суцільні лінії або вертикальні градієнти), тому адаптивний вибір підвищує підсумковий коефіцієнт стиснення.
7. **Обсяг службових байтів:** Додається ровно 1 байт на кожен рядок. Для 384 рядків це 384 байти, що є мізерним обсягом порівняно із загальним виграшем у сотні кілобайт.
8. **Чому ентропія за гістограмою не була межею:** Початкова ентропія вимірювала лише незумовлену частоту окремих пікселів без урахування просторових зв'язків. Фільтри прибирають просторову надлишковість.
