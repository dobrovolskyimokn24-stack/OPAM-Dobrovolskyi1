## Завдання 1. Лінійний пошук
- Третій запит ("Я-99") найдорожчий, бо елемента немає у масиві, і програмі довелося перевірити абсолютно всі 100 000 елементів до кінця.

## Завдання 2. Прояв поломок бінарного пошуку
1. **`while (lo < hi)`**: Не знаходить елементи, коли `lo == hi` (останній елемент масиву повернув -1).
2. **`lo = mid`**: Програма зависає у нескінченному циклі, бо межі перестають зміщуватися при розділенні.
3. **`mid = (lo + hi) / 2`**: Не ламається на 100 000 елементів, оскільки сума індексів не перевищує межу `int` (2 147 483 647).
4. **`Невпорядкований масив`**: З 100 наявних елементів пошук повернув -1 для більшості (близько 85%).

## Завдання 3. Пошук межі
- Кількість порівнянь не залежить від кількості дублікатів X, бо алгоритм завжди робить однакову кількість ділень навпіл ($\log_2 N$).
- Предикат з цифрою 7 дає невірний результат, бо масив не відсортований за цією цифрою (умова немонотонна).

## Завдання 4. Потрійний пошук
- Кроків стало менше (ділимо на 3 частини), але порівнянь стало більше, бо на кожному кроці робиться по 2 перевірки.

3. Для потокових даних краще вибрати `HashSet` або динамічне дерево, бо сортувати масив після кожного нового елемента занадто дорого.
